# API · ERD 검토 결과

검토일: 2026-11-11 · 명세 v0.2

## 검토 기준과 범위

- 최초 검토(2026-11-11) 기준: 기획 1차 수정본 MD와 사용자가 첨부한 IA 차트 이미지. 이번 공유본의 `서비스_요구사항.md`는 그 기획의 제품 흐름을 2026-11-12에 재구성한 요약입니다.
- 저장소에서 원본 기획 PDF는 찾지 못했습니다. 기획 MD에 기록된 요약과 첨부 IA를 기준으로 대조했습니다.
- API·ERD의 설계를 수정했으며 백엔드 코드·DB 마이그레이션은 변경하지 않았습니다. 기획 MD도 원문을 유지했습니다.
- 기획의 통계·연구·의료/법률 근거 자체의 검증은 이번 설계 검토 범위에 포함하지 않았습니다. 기존 수치 기준은 프로젝트 정책으로만 표기했습니다.

## 검토 과정에서 제안한 보완 정책

아래는 기존 기획을 그대로 옮긴 확정 요구사항이 아니라, 빠진 예외 흐름을 연결하기 위한 **v0.2 설계 제안**입니다. 팀 합의 후 구현하세요.

- 건강정보 동의를 선택으로 유지하는 기존 명세에 맞춰, 비동의자는 CBI 건너뛰기 후 일정 기능을 사용하도록 제안했습니다. CBI·컨디션도 해당 동의의 보호 범위에 포함하고 건강 기록 삭제 API의 범위를 명확히 했습니다. 약관·동의 문구 검토는 별도로 필요합니다.
- 수동 입력은 RMSSD만 받고 UNVERIFIED 참고값으로 표시하며 자동 기준선에는 넣지 않도록 제안했습니다. 수동값을 자동 계산에 넣으려면 기기·지표·품질 확인 정책을 추가해야 합니다.
- Idempotency-Key 최소 24시간, 건강 기록 전체 삭제 범위, 완료한 제안의 undo 금지, 현재 날짜 측정만 허용은 구현을 위한 제안 규칙입니다.
- 계산 정책 미확정인 결과는 POLICY_PENDING으로 표시하고 해당 생성 작업은 422로 반환하도록 제안했습니다. 화면에 가짜 점수를 채우지 않기 위한 임시 계약입니다. (v0.3: 일정 부하·회복·2주 연속 낮음·범위 위치는 [계산_정책.md](계산_정책.md)로 확정)

## Come-down 구조 설계 추가 (2026-11-12)

서비스명을 Come-down(캄다운)으로 반영했습니다. 신규 구조는 API·ERD·IA·서비스 요구사항에서 설계했으며 기존 소스 구조를 기준으로 하지 않았습니다. [구조 설계](백엔드_구조설계.md)와 [책임 매핑](책임_매핑.md)을 추가했습니다. 이전 브라우저 검증 기록은 해당 시점 명세 HTML에 대한 기록이며 신규 구조의 서버 구현 검증을 의미하지 않습니다.

당시 공유본의 HTML 7개를 Chrome의 PC·390px 모바일 화면에서 검증했습니다. 이름 표기·가로 넘침·책임 매핑 개수·API 검색·안내 링크·JavaScript 오류 등 27개 검사가 통과했습니다. API 39개·테이블 18개의 책임 매핑을 명세와 대조했고, 공유 ZIP 내부 링크와 기존 구현 클래스/패키지 참조 유입도 검사했습니다. 실제 서버 구조를 생성하거나 실행한 검증은 아닙니다.

## 팀장 수정 요청 1 반영 (2026-11-12, 명세 v0.3)

"백엔드 설계 수정 요청 1"의 1장(필수 수정)·2장(정책 확정 값)을 API·ERD·기준선 migration·[계산_정책.md](계산_정책.md)에 반영했습니다. 참고 구현 `HrvAnalyzer`는 `checkin.domain.measurement`에 그대로 옮기고(패키지·버전 상수만 추가) 합성 신호 테스트를 붙였습니다.

| 요청 | 반영 위치 |
|---|---|
| 1-1 측정: 밝기 배열 전송, 서버 RMSSD 계산 | API 6절 요청·검증, ERD·migration `hrv_measurements`(noise_ratio·retry_reason·algorithm_version·time_source·frame_count·channel, RETRY 행은 rmssd null) |
| 1-2 측정 → 컨디션 → 호흡 → 결과 | API 6절·10절, ERD `morning_checks`, 서비스 요구사항 |
| 1-3 retryReason | API 측정 응답, ERD `retry_reason`, enum RetryReason |
| 1-4 CBI 보기·문항 | API 2절(13문항 표), 계산 정책 2절, `cbi-ko-2026.11.2` |
| 1-5 하루 대표값 = 첫 적격 측정 | ERD `hrv_daily_states`, 계산 정책 4절 |
| 1-6 GOOD → NORMAL | API·ERD RecoveryStatus |
| 1-7 AI_NOTICE 필수 | API `PUT /api/onboarding/profile` 검증, ERD consent 설명 |
| 2-1 ~ 2-5 | 계산 정책 1·4·5·6절, API WeekLoad·안전 안내·범위 위치 |

요청에 없던 보완:
- `weekly_loads.vs_usual_unavailable_reason` 컬럼과 WeekLoad `vsUsualUnavailableReason` 필드를 추가했습니다. `ZERO_BASELINE`과 `INSUFFICIENT_DATA`를 저장값만으로 구분하기 위해서입니다.
- `hrv_measurements`에 CHECK 2개를 추가했습니다. RETRY가 아니면 RMSSD 필수, RETRY일 때만 retry_reason이 있어야 합니다.
- MANUAL 측정의 `algorithm_version`은 `manual-v1`로 둡니다(컬럼이 NOT NULL).
