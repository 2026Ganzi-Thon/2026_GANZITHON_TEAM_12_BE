이 버전표는 기존 협업 논의에서 가져온 제안이며 최신 버전 추천이나 신규 구조 구현 결과가 아니다. 구조 설계는 이 버전/기존 구현과 독립적으로 API·ERD·제품 흐름으로 결정했다. Java 패치/공급사와 MySQL 이미지 digest는 팀에서 확정해야 한다. 버전 변경은 기능 PR과 분리해 두 개발자가 함께 갱신한다. Node/npm·프론트 폴더는 백엔드 구조에 포함하지 않는다.

작업과 리뷰

  • 이슈에 담당·수정 패키지·입출력 계약·API/DB 영향을 남긴다. 계약은 구조 문서의 contract 경계를 따른다.
  • feat/이슈-기능, fix/이슈-수정, docs/주제 브랜치. AI가 새로 만들면 codex/주제.
  • main 직접 push·공유 브랜치 force push 금지. 기능별 작은 PR, 상대 1인 리뷰 후 squash merge.
  • 공통 설정·보안·외부 어댑터·migration·명세는 수정할 사람이 먼저 알리고 같은 파일의 중복 편집을 피한다.
  • 기능 간 Repository/Entity import, feature→experience, shared→기능, integration→기능 application 의존을 리뷰에서 확인한다.
  • 테이블 쓰기 소유권과 HTTP 책임이 바뀌면 architecture-map.json과 API/ERD를 같은 PR에서 갱신한다.
  • MD/JSON이 원본이다. python docs/build_spec_html.py로 HTML과 책임 매핑을 재생성한다(Python/markdown-it-py는 문서 생성에만 필요).

DB와 검증

새 migration은 VYYYY_MM_DD_HHmmssSSS__description.sql(UTC 시각). 버전 중복·병합 순서를 확인한다. 아직 공유/적용하지 않은 새 파일만 main 이후 버전으로 조정할 수 있다. 공유/적용한 파일은 보정 migration으로 변경한다. JPA ddl-auto=validate, DB 초기화나 repair로 충돌을 숨기지 않는다.

신규 프로젝트 골격과 테스트 구성을 만든 뒤 저장소 루트에서 실행할 명령:

.\scripts\check-backend-env.ps1 -RequireDocker -RunGradle
.\gradlew.bat test
.\gradlew.bat check bootJar
python docs/build_spec_html.py

순수 계산·API 동의/소유권·MySQL 제약·복합 흐름 실패/재시도·탈퇴/삭제를 검증한다. 테스트 패키지는 main 기능 구조와 맞추고 공통 fixture는 test/support에 둔다. 외부 호출은 대체 응답, 시간은 고정 Clock, DB는 동일한 MySQL 이미지로 검증한다. Docker 미가동·skip과 실제 실패를 PR에서 구분한다.

CI·main 보호·승인 1인 규칙은 실제 레포에서 설정한다. 문서나 PR 템플릿만으로 자동 강제되는 것은 아니다.

비밀값과 서비스 식별자

.env, 토큰, 키, 원신호, 실사용자 일정/건강정보는 공유 묶음과 Git에서 제외한다. 환경변수 실제 값과 OAuth 테스트 사용자 등록·콜백 URL은 별도로 안전하게 전달한다. 서비스명을 바꿨다고 기존 DB명·키·OAuth 설정을 조용히 바꾸지 않는다. 신규 설정 예시는 Come-down 기준으로 제공하며 기존 환경 전환은 별도 PR로 검토한다.
