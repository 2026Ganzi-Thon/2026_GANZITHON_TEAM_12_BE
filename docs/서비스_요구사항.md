# Come-down(캄다운) 서비스 요구사항

2026-11-12 · 백엔드 구조 설계용 제품 요구사항 요약

서비스명은 **Come-down(캄다운)**이다. 코드 네임·DB명·환경변수는 별도 기술 식별자이며 서비스 표시명을 바꾼다고 저장된 인증정보나 DB를 자동으로 변경하지 않는다. 신규 Java 패키지 제안은 com.comedown이다.

기준은 기존 기획 1차 수정본의 제품 요구사항·첨부 IA·API/ERD다. 이 요약은 기존 구현 상태/클래스/패키지 설명을 제거하고, 개발할 서비스 전체를 기준으로 작성했다. 세부 계약은 [API](API.md), 데이터는 [ERD](ERD.md), 미확정 정책은 [검토 결과](검토결과.md)를 따른다.

## 사용자 흐름

1. 구글 로그인, 닉네임·연령·약관/개인정보·캘린더 동의 확인.
2. CBI 13문항, 생활 정보(측정 시간·수면 시간대·선호 회복 활동), 캘린더 연결/분석, 온보딩 완료.
3. 홈에서 오늘 회복·이번 주 일정 부하·추천·체크 진행 확인.
4. 캘린더에서 분류 직접 수정, 앞으로 4주 위험 주차·마감 몰림·미리 시작할 작업 블록 확인.
5. 아침 HRV 측정 → 컨디션(1~5, 음주·아픔·카페인) → 1분 호흡(건너뛰기 가능) → 회복/추천 결과.
6. 추천을 승인하면 빈 시간에 캘린더 등록. 건너뛰기·다른 시간·되돌림·수행 체크 지원.
7. 적격 측정 7일 확보 후 회복 리포트, 28일차 CBI 비교·회복/부하 범위 위치. 부족한 자료와 동의 상태에 따른 별도 표시.
8. 마이페이지에서 닉네임/생활 정보·동의·연결 관리, 건강 기록 삭제·탈퇴, 용어 사전·도움 안내.

## 백엔드의 핵심 데이터 책임

- 계정·동의·Google 자격정보·생활 정보·온보딩 상태.
- CBI 문항 버전·응답·회차·하위척도 점수.
- 캘린더 일정·사용자 분류 규칙·주간 부하·위험 주차.
- 아침 체크·여러 측정·컨디션·일별 기준선/추세/회복 상태.
- 과부하 대비 PRE_START 및 회복 RECOVERY 추천·승인/거절/수행 이력.
- AI 해석 캐시·생성/대체 표시, 안전 안내, 체험/이용 자격, 중복 요청 처리.

## 제품 제약

- 초기에는 단일 백엔드·단일 DB로 구현한다. 프론트는 별도 저장소이며 계약으로 연결한다.
- 카메라 영상은 서버에 보내지 않는다. 측정 원신호(프레임별 밝기 배열)는 서버가 RMSSD 계산에만 쓰고 저장하지 않는다(v0.3). Google 일정 제목은 영구 저장하지 않는다.
- 기준선/회복/CBI/일정 부하는 코드로 계산한다. AI는 분류·해석·문구를 보조하며 실패 시 규칙 기반으로 대체한다.
- 운영 인증·동의·다른 사용자 접근 차단, 탈퇴/철회 시 원본·파생·캐시 정리가 필요하다.
- 4주 체험/유료 자격 표시는 포함하지만 결제 API는 현재 명세 범위에 없다. 용어 사전은 정적 콘텐츠다.
- 회복 수치와 안전 안내는 프로젝트 표시 정책이며 의료 진단이 아니다. 지원 연락처는 공식 확인 후 등록한다.

## 함께 결정할 정책

기준선·회복 산식, 일정 가중치·종일/겹친 일정 집계, LOW 연속 2주, 안전 안내 재노출, 4주 범위 위치는 [계산 정책](계산_정책.md)으로 확정했다(v0.3). 남은 항목은 컨디션 기반 추천 임계값, 민감정보 선택 동의 흐름, 알림/탈퇴 시 외부 일정 정리와 [검토 결과](검토결과.md) 마지막 절의 확인 항목이다. 이 항목을 기존 코드의 동작으로 대신 확정하지 않는다.
